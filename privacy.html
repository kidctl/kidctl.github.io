Privacy

kidctl is software you run, not a service. There is no kidctl account, no kidctl cloud, and nothing is ever sent to the people who write it.

What the phone sends, and to whom

The agent talks to one place: the server address you gave it. About once a minute it sends:

  • the time spent today in each app, in seconds of foreground use;
  • the list of installed apps (name, package, whether the child installed it, whether it is paused), only when it changes;
  • the agent's version, the Android version, the version of the rules it applies, and whether it is still device owner;
  • events and errors: the phone booted, a notice shown to the child, an app configuration applied (values of keys that look like secrets are shown as <redacted>), a setting Android refused, an update installed.

The server answers with the rules and, when you publish one, an agent update, which the phone downloads from the same server. That's the whole conversation. Notifications to the child are written and shown by the phone itself: no push service is involved.

What it never collects

Messages, calls, contacts, photos, browsing history, notifications, screen contents, keystrokes, location. The rules can keep location switched on, so that you can find a lost phone with Android's usual tools, but kidctl itself never reads or sends it. The agent has no third-party code at all: no analytics, no crash reporter, no advertising library.

Where it lives

  • Usage: in one SQLite file on your server. Delete it and it's gone.
  • Rules: in your git repository, readable by whoever you give access to.
  • Secrets: the server stores only SHA-256 hashes of the phones' tokens and of the OAuth tokens it hands to Claude, and an argon2id hash of your owner password. If Claude may change rules, the server also holds an ssh deploy key for your rules repo, and nothing else.
  • Abuse protection: every request is rate-limited, and an address that keeps failing to authenticate is banned for an hour. A banned address still gets answers to requests with valid credentials, so a household sharing one internet address is never locked out by failed attempts coming from that address.

If you connect Claude

Claude only sees what you ask about. When it reads usage, the app list, events or a rules file through MCP, that data becomes part of your conversation, under the terms of your Claude account. When it changes a rule, the change is a commit in your repo that records which client asked for it. Connecting a client takes your owner password. Don't connect it if you'd rather not: everything works from git alone.

Google

The phone is still an Android phone, usually with a Google account. Google's own services work, and collect, as they normally do; kidctl adds nothing to that.

Tell your child

kidctl works best out in the open. Show the rules to your child, explain what they can see and what you can see, and change the rules together as they grow up. The file is short enough to read together.
