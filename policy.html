Rules

A summary of the format. The complete reference is docs/POLICY.md, and every Android control with its API is in docs/CONTROLS.md.

Files

<child>.yamlThe child's rules. The file name matches child:.
<child>.overrides.yamlTemporary exceptions, each with an expiry (overrides: [] when there are none; Claude needs the file to exist).
devices.yamlPhones allowed to sync, whose they are, and the hash of their token. Only you edit it, never Claude.

Run kidctl validate <dir> (or ask Claude to) before pushing. The server refuses an invalid directory and keeps the previous rules.

The child's rules

child, timezone
Lowercase name, and an IANA time zone (Europe/Paris) that defines “today” and every clock time.
downtime
Windows when only always-allowed apps work: {start: "21:00", end: "07:00"}. They may cross midnight; days restricts a window to the days it starts; lock_screen: true also keeps the screen locked.
always_allowed
Never limited, usable during downtime: the phone app, maps, school apps.
blocked
Never usable.
approval, approved
With approval: true, an app the child installs stays paused until it is named in approved, always_allowed or a limit.
limits
Daily budgets for groups of apps. apps: ["*"] means every app not always-allowed or excluded. An app must have time left in every limit that matches it.
notify
Notifications for the child, off unless present: notify: {} turns them on with the defaults (see below).
device
Settings of the phone itself (see below).
limits:
  - name: games
    apps: [com.mojang.minecraftpe]
    daily: {weekdays: 45m, weekend: 2h}
  - name: video
    apps: [com.google.android.youtube]
    daily: {wed: 1h, default: 30m}     # 0 = blocked that day
    notify_at: [80]                    # this limit's own thresholds ([] = none)

Durations: 1h30m, 45m, 2h, 90s, 0. Day keys: mon…sun, weekdays, weekend, default; the most specific wins, and every day must end up with a value. Usage is foreground time since local midnight, summed over all the child's phones.

Evaluation order

For each app, about every 30 seconds, on the phone:

  1. blocked → blocked
  2. always_allowed → allowed
  3. approval on and the app named nowhere → blocked until approved
  4. active unlock override → allowed
  5. active lock override → blocked
  6. inside downtime → blocked
  7. any matching limit used up (plus extra time) → blocked
  8. otherwise allowed

A blocked app shows Android's “App paused” dialog. Never paused: the agent, the launcher, Settings, the phone app, emergency apps and the Play Store.

When a lock with screen: true or a lock_screen downtime applies, the screen itself locks, and locks again a second after every unlock; always-allowed apps are behind the lock screen too. The lock screen's Emergency call button still works (set a PIN on a child's phone), and an ongoing call is never cut off: the lock waits for the call to end.

Notifications

notify:
  quota_at: [50, 80, 95]   # % of each limit's budget (the default)
  before_downtime: 5m      # notice before downtime (default 5m, 0 = none)
  locale: en               # fr (the default) or en

The child gets “Games: 80% used. 9 min left today.” and “Downtime at 21:00. The phone pauses in 5 min.” Each threshold notifies at most once per limit and day; extra time arms the thresholds above the new percentage again; nothing is notified while an unlock, a lock or downtime decides anyway. A limit's own notify_at replaces quota_at for it. Each notice is reported as an event, and Claude's status shows the thresholds reached today.

Overrides

overrides:
  - {extra: 30m, limit: games, until: "2026-11-07T21:00", note: "homework done"}
  - {extra: 15m, until: "2026-11-05T21:00"}                  # every limit
  - {lock: true, until: "2026-11-04T18:30"}                  # homework
  - {lock: true, screen: true, until: "2026-11-04T21:00"}    # screen locked too
  - {unlock: true, from: "2026-12-31T18:00", until: "2027-01-01T01:00"}

from defaults to now; times are in the child's time zone (or RFC 3339; Claude also takes +30m from now). Expired entries are ignored; delete them when convenient, or ask Claude to prune them.

Device controls

The device: section is applied once per rules version; what depends on an app (its configuration, a default app) is applied again when that app is installed:

restrictions
Android user restrictions: no_factory_reset, no_safe_boot, no_config_date_time, no_add_user, no_modify_accounts, no_install_unknown_sources_globally, no_config_vpn, disallow_config_private_dns, no_config_tethering, disallow_config_default_apps, no_debugging_features…
hidden, uninstall_blocked
Apps removed from the launcher; apps that cannot be uninstalled (the agent itself always is).
user_control_disabled
Apps that cannot be force-stopped, or their storage cleared, from Settings, and that get no Stop button in Quick Settings › Active apps. no_control_apps alone leaves that button, and a stopped VPN app is not restarted by Android. The agent itself is always protected.
camera_disabled, screen_capture_disabled
Camera and screenshots off.
always_on_vpn, private_dns
A VPN app that Android keeps running, optionally with lockdown (no traffic without it); a forced Private DNS host for filtering (removed: back to Android's Automatic).
app_config
Managed configurations: the keys an app declares for its administrator, which the user then cannot change in the app. com.tailscale.ipn: {ForceEnabled: true} keeps Tailscale's own switch on. The agent checks each key and value against what the app declares, and reports what it applied.
wifi_ssids
{allow: [...]} or {deny: [...]}. An allow list blocks every other network, at school and at friends' too: prefer a deny list.
default_apps
Locked default launcher and browser (for the browser, hide the other browsers: Android asks its browser role first).
permitted_input_methods, permitted_accessibility_services
Allowed keyboards and accessibility services.
auto_system_updates, location_always_on
OS updates installed automatically; location kept on.
lock_screen_info, support_message, organization_name
Texts shown on the lock screen, on blocked settings, and as “This device belongs to …”.
device:
  restrictions: [no_factory_reset, no_safe_boot, no_config_date_time, no_config_vpn]
  always_on_vpn: {package: com.tailscale.ipn, lockdown: true}
  private_dns: {mode: host, host: dns.example.org}
  uninstall_blocked: [com.tailscale.ipn]
  user_control_disabled: [com.tailscale.ipn]
  app_config:
    com.tailscale.ipn:
      ForceEnabled: true                 # its own switch stays on
      UseTailscaleDNSSettings: always    # the tailnet's (filtering) DNS
      Hostname: alex-phone
  organization_name: kidctl
  lock_screen_info: "Alex's phone. Found it? Call 555 0100."

Problems the phone reports

Every device setting goes through Android's device-policy API and, wherever Android lets the agent read it back, is checked afterwards. Anything that fails or doesn't hold becomes an event, once while it lasts: restriction_failed, vpn_failed, private_dns_failed, app_config_failed (not declared by the app, did you mean Hostname?), user_control_disabled_failed, default_app_ineffective, suspend_failed… The agent tries again at the next rules change or app install. Claude's list_children and status show, per phone, policy up to date or policy behind: has X, served Y, and its last error.

Changing rules through Claude

With the server's GitOps writes set up (how), Claude connected over OAuth can change every rule. Each tool edits only <child>.yaml or <child>.overrides.yaml, keeps the file's comments and layout (only the lines that change are touched), validates the whole directory like kidctl validate, commits as kidctl-mcp: <tool> <child>: <summary> with a Requested-By: line, and pushes. If someone pushed meanwhile, it re-applies the change on top and tries once more.

add_overrideextra time, a lock (optionally with the screen) or an unlock, until a time
remove_override, prune_overridesone exception, or every expired one
approve_appan app into approved, always_allowed, a limit, or approved outside every "*" limit
block_app, unblock_appblocked
set_limita limit's apps, exclusions, daily budgets and notification thresholds, or a new limit
set_downtimethe downtime windows
set_deviceany device: setting, or its removal
write_policythe whole file, for anything else; refused unless the file is still the revision Claude read (policy_source), so a concurrent edit is never overwritten
policy_source, validate_policyread a file with its comments and revision; check a candidate file

Every write tool takes a dry run: the diff and the validation result, nothing committed. Claude never writes devices.yaml and never creates a file, and the write tools need the owner password (OAuth).
